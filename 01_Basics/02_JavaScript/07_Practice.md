# 07. Практические задания

## Как начать

Задания рассчитаны на постепенное изучение языка. Сначала прочитайте [настройку окружения](02_Setup.md), откройте терминал в папке 02_JavaScript. Команда node запускает указанный файл. Тест — автоматическая проверка ожидаемого результата.

Самый простой вариант — начать с задания 3: открыть report.html в браузере, поменять регион и посмотреть, как меняется итог. Для остальных заданий с Node.js понадобится установленная среда выполнения.

API в задании 4 — учебный сервер на собственном компьютере. После запуска откройте в браузере полный адрес http://127.0.0.1:3000/api/report. Для остальных вариантов меняйте окончание адреса. Код 200 означает успешный ответ, 400 — неправильный запрос. Остановить сервер можно через Ctrl+C.

В заданиях приведены ожидаемые результаты, а не подтверждение, что они уже выполнены.

## Задание 1. Обработка массива

Запустите node examples/sales.mjs. Добавьте новую строку с суммой 40000. Объясните, как изменится общий итог и выборка с порогом 80000. Ожидается новый итог 300000, выборка по порогу не изменится.

## Задание 2. Тесты

Запустите node --test examples/sales.test.mjs. Добавьте тест, проверяющий выбор региона Казань с порогом 90000. Ожидается пустая выборка. Изучите разницу между ожидаемым и фактическим результатом при падении теста.

## Задание 3. Интерфейс

Откройте examples/report.html. Проверьте фильтры и сброс. Добавьте вывод количества видимых строк. Проверьте случаи: все строки, одна строка, пустая выборка.

## Задание 4. API

Запустите node examples/server.mjs. Проверьте /api/report, /api/report?min=80000 и /api/report?min=abc. Сравните ответ и HTTP-статус. Объясните, почему проверка параметров выполняется на сервере.

## Задание 5. Связь с Python и ML

Создайте аналог фильтра и суммы на Python, используя список словарей. Сравните результат с JavaScript. Представьте, что вместо суммы продаж сервер возвращает прогноз модели: какие поля нужны интерфейсу для отображения результата и ошибки?
