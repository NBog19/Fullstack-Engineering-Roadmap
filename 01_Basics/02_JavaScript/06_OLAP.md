# 06. JavaScript в аналитических системах

## Пример отчёта

| Город | Январь | Февраль | Итого |
| --- | ---: | ---: | ---: |
| Москва | 70000 | 50000 | 120000 |
| Казань | 30000 | 50000 | 80000 |
| Сочи | 20000 | 40000 | 60000 |
| Все города | 120000 | 140000 | 260000 |

Если выбрать только Москву, итог станет 120000. Если поменять местами города и месяцы, получим другое представление тех же данных. В этом состоит идея многомерного анализа.

Frontend — видимая часть приложения. Backend — серверная часть, которая обрабатывает запросы и возвращает данные. API связывает эти две части.

JavaScript помогает обновить таблицу после выбора фильтра. При больших объёмах сервер обычно рассчитывает итог, а браузер показывает результат.

Виртуализация таблицы означает, что браузер создаёт видимые элементы только для части строк, а не для всего огромного отчёта одновременно. Постраничная загрузка означает получение данных небольшими порциями. Эти подходы могут использоваться вместе, но решают разные задачи.

OLAP позволяет анализировать показатели по нескольким измерениям: например, продажи по регионам, товарам и месяцам. JavaScript помогает построить интерфейс, в котором можно выбирать измерения, фильтры и показатели.

| Термин | Пример |
| --- | --- |
| Измерение | Регион, месяц, товар |
| Показатель | Сумма продаж |
| Фильтр | Только Москва |
| Агрегация | Сумма продаж по региону |
| Pivot | Перестановка измерений по строкам и столбцам |

## Распределение ответственности

```mermaid
flowchart LR
    U[Пользователь] --> F[Frontend]
    F --> A[API]
    A --> S[Сервер аналитики]
    S --> D[Хранилище данных]
    D --> S
    S --> A
    A --> F
```

Клиент отображает таблицу и управляет действиями пользователя. Сервер проверяет права, валидирует параметры и выполняет тяжёлые вычисления. Передача всех исходных данных в браузер может быть неэффективной и недопустимой по правилам доступа.

## Учебный контракт API

GET /api/report?region=Москва&min=80000

Ответ: объект с rows и total. В учебном сервере total означает сумму отфильтрованных строк, а не полный итог всей базы.

## Производительность и корректность

Для больших таблиц применяют постраничную загрузку или виртуализацию отображения. При группировке важно определить правила для отсутствующих значений, округления и итогов. Среднее от средних не всегда равно общему среднему: необходимо учитывать количество записей.

## Вопросы разработчику

- Где вычислять итог для миллионов записей и почему?
- Как предотвратить появление устаревших результатов запроса?
- Как отобразить пустую выборку?
- Как проверить, что итог соответствует фильтру?
- Почему нельзя полагаться только на клиентскую проверку прав?

Пример курса — небольшая имитация аналитического интерфейса, а не полноценный OLAP-движок. Архитектура конкретного корпоративного проекта требует отдельного уточнения.
