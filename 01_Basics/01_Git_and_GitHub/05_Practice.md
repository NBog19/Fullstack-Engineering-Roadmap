# 05. Практика GitHub без консоли

Для начала используем отдельный учебный репозиторий git-training, созданный по [инструкции](02_Setup.md). Не меняем рабочий проект компании.

## 1. Создать первый файл

Откройте проект на GitHub. Нажмите Add file → Create new file. Назовите файл report.md и напишите:

~~~text
# Отчёт
Москва: 120000
Казань: 80000
Итого: 200000
~~~

Нажмите Commit changes, напишите «Первый отчёт» и подтвердите. Файл появится в проекте.

## 2. Посмотреть историю

Откройте report.md, нажмите значок карандаша (Edit). Добавьте Сочи: 60000 и замените итог на 260000. Снова нажмите Commit changes с описанием «Добавлен новый город».

Откройте историю файла (History). Найдите обе сохранённые версии. Так можно увидеть, что именно поменялось.

## 3. Создать черновик

Создайте ветку feature/report-filter по [шагу 2 главы Workflow](03_Workflow.md). Переключитесь на неё и добавьте в отчёт фразу «Планируется фильтр по городам». Сохраните изменения. Переключитесь на main: там новой фразы пока нет.

## 4. Объединить работу

Откройте Pull requests → New pull request. Выберите main как основную ветку и feature/report-filter как ветку с изменениями. Создайте запрос, откройте Files changed и посмотрите добавленную строку. Если всё правильно, объедините запрос через Merge pull request.

Ожидаемый результат: новая фраза появится в основной ветке.

## 5. Дополнительно: конфликт

Если два человека меняют одну строку по-разному, Git может попросить выбрать правильный вариант. Например, один предлагает вычесть скидки, другой — возвраты. Если по условию нужны оба вычета, итог при выручке 100, скидках 5 и возвратах 10 равен 85.

Подробнее о конфликтах — [Workflow](03_Workflow.md). Это дополнительная тема, не обязательная для первого знакомства.
