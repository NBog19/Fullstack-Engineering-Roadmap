# 02. Установка и настройка

## Рекомендуемый способ: создать проект на сайте GitHub

Для новичка удобнее начать с браузера: откройте [github.com/new](https://github.com/new), введите имя проекта, выберите Private, включите Add README и нажмите Create repository. Подробные шаги, включая создание файлов и веток, приведены в [главе о рабочем процессе](03_Workflow.md#8-практика-работа-прямо-на-сайте-github).

Если нужно только создавать и читать учебные документы, терминал не нужен. Следующая часть предназначена для разработчиков, которым необходимо запускать код на своём компьютере.

## Что понадобится и зачем

Если нужно только читать инструкции на GitHub, ничего устанавливать не требуется. Для самостоятельного изменения файлов на компьютере нужен Git. Терминал — окно, в которое вводятся текстовые команды; VS Code — редактор, в котором удобно менять файлы.

Команды ниже выполняются по одной, нажимая Enter после каждой. Текст в кавычках Your Name и YOUR_EMAIL нужно заменить своими данными. Настройки с --global действуют для всех локальных репозиториев данного пользователя.

| Команда | Простое назначение |
| --- | --- |
| mkdir | Создать папку |
| cd | Перейти в папку |
| git init | Начать отслеживание истории проекта |
| echo ... > README.md | Создать или перезаписать файл с указанным текстом |
| git status | Посмотреть, что изменилось |
| git add | Подготовить изменения к сохранению |
| git commit | Сохранить версию |
| git log | Посмотреть сохранённые версии |

Учебную папку следует создавать отдельно от существующих проектов. Команда с символом > перезаписывает файл, поэтому используйте её только для нового учебного README.

## Установка

На macOS откройте Terminal и проверьте:

```bash
git --version
```

Если Git отсутствует, macOS может предложить установить инструменты командной строки Apple. Также можно использовать официальный сайт Git. Для Windows доступен Git for Windows, для Linux — пакетный менеджер дистрибутива, например apt в Debian и Ubuntu.

- [Установка Git](https://git-scm.com/downloads)
- [Начало работы с GitHub](https://docs.github.com/en/get-started)

## Настройка автора

```bash
git config --global user.name "Your Name"
git config --global user.email "YOUR_EMAIL"
git config --global init.defaultBranch main
git config --list
```

Имя и адрес используются в метаданных коммитов, но не предоставляют доступ к GitHub. Для защиты личного адреса можно использовать адрес noreply из настроек GitHub. Не публикуйте личные настройки и токены в учебных материалах.

## Дополнительная практика: локальный учебный репозиторий через терминал

Это альтернативный способ для упражнений по Git. Если репозиторий уже создан на GitHub и нужен на компьютере, вместо git init используйте git clone с его адресом. Для заданий из 05_Practice.md можно создать отдельный локальный каталог, как показано ниже.

```bash
mkdir git-training
cd git-training
git init
echo "# Git training" > README.md
git status
git add README.md
git diff --staged
git commit -m "Create training README"
git log --oneline
```

Ожидаемый результат: один коммит и чистое состояние рабочей папки. SHA и дата будут индивидуальными.

## Работа с GitHub

На сайте можно создать отдельный учебный репозиторий. Для существующего репозитория удобнее использовать git clone с его HTTPS-адресом. При работе с приватным репозиторием потребуется авторизация — например через Git Credential Manager или настроенный SSH. Пароль аккаунта не используется как пароль для Git-операций через HTTPS.

Проверить привязанный удалённый репозиторий:

```bash
git remote -v
```

## Игнорирование файлов

Пример .gitignore для будущего проекта:

```gitignore
node_modules/
dist/
.env
.env.local
*.log
```

Правила не удаляют уже отслеживаемые файлы из истории. Если секрет попал в репозиторий, нужно сообщить ответственному за безопасность и отозвать или заменить секрет.

## Контроль результата

- Git отвечает на git --version.
- Создан отдельный учебный каталог.
- История содержит первый коммит.
- Личные данные и секреты не включены в учебные файлы.

Иллюстрации интерфейса лучше добавлять после самостоятельного выполнения этих шагов: внешний вид зависит от ОС и версии GitHub.
